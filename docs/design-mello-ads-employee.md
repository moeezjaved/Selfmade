# Design: Mello as an Ad-Ops Employee (answer + act)

## Problem Statement
A Selfmade user should be able to type a plain question — "what do I need to do to improve my ads?" — and have Mello answer it truthfully and then *take the action* on a yes (pause the loser, scale the winner), reversibly. Today Mello's chat "isn't answering." Not because it's dumb, but because the chat agent isn't grounded in the audit Selfmade already computes, so it hangs or waffles. The long-term vision is the same brain reachable from Slack / WhatsApp / SMS, but that is expansion, not the wedge.

## Demand Evidence
- Real, live surface: Meta OAuth is live, 7 ad accounts connected, real spend/ROAS flowing (€98 → €225, 2.31x on ROY 1; $687k+ aggregate across accounts).
- The founder already reaches for this exact question ("what do I need to do to improve my ads") as the one task they'd use daily.
- **Honest gap:** demand for *this answer* is proven (Reports + the brief card get used). Demand for *Mello-as-agent* specifically (chat it, it acts) is assumed, not yet measured. That's the risk to retire first (see Assignment).

## Status Quo
- Selfmade already answers the question, twice: the brief's Facebook Ads card and Reports → "What Mello would do" both output scale/watch/pause with expected impact and one-click execution (`src/components/brief/FacebookAdsCard.tsx`, `src/components/reports/ReportsNarrative.tsx` §8).
- The scale/pause *actions* already exist as approve→act tasks (`mello_tasks` + `tasks/run`, migration 126).
- So the user's current workaround is: open a report, read it, click the action. The chat box is the missing doorway — and it currently dead-ends.

## Target User & Narrowest Wedge
- **User:** a founder-operator running Meta ads inside Selfmade (has ≥1 connected account with spend).
- **Wedge:** typing "how do I improve my ads?" (or any close paraphrase) returns *one grounded sentence* from the audit we already compute, plus the existing one-click Scale/Pause actions inline — and on "yes," it executes and can be reverted. One question, one place, every time, no hang.

## Constraints
- v1 rides **Meta's reported ROAS**. Shopify/true-ROAS is a later upgrade to the same engine, not a prerequisite.
- **Approve → act only.** Mello never changes spend without an explicit yes. Every action is reversible (pause ↔ resume; budget change logged with the prior value).
- **Must not hang.** The current `src/lib/mello/agent.ts` tool-loop stalls; the money question must never route through an open-ended loop that can hang.
- Reuse what exists: `auditAccount()` (`src/lib/meta/audit.ts`), `mello_tasks`/`tasks/run`, `MetaClient` action methods (`pauseCampaign`, `scaleCampaignBudget` in `src/lib/meta/client.ts`).

## Premises (agreed in session)
1. The wedge is one job done superbly — answer + act on ad improvement — not "do all company tasks."
2. v1 uses Meta ROAS; Shopify true-ROAS is a later intelligence upgrade.
3. Every action is propose → confirm → execute → reversible. No autonomous spend changes.
4. Slack/WhatsApp/SMS come *after* Mello reliably answers-and-acts in one place. The "propose, confirm, execute" contract is channel-agnostic, so getting it right once makes those channels nearly free.
5. "Not answering" is a grounding/wiring bug, not an intelligence gap. Fix grounding first; add reasoning second.

## Intelligence ladder (ranked by leverage, not impressiveness)
1. **Reliable grounded answers** (fix now) — the chat reads `auditAccount()`, not an open loop.
2. **Reasoning over grounded data** (next) — a strong model reasons over the *audit result* (fatigue, frequency, CPM drift), proposes actions through the same confirm→execute gate.
3. **Per-account memory** (later) — "last time we scaled this it fatigued in 4 days."
4. **True ROAS via Shopify** (later) — the biggest accuracy jump; deferred by the founder.

## Approaches Considered
### Approach A: Grounded router (minimal viable)
When the user's message is an ad-performance question, skip the open agent loop entirely. Detect intent → call `auditAccount(userId, accountId, range)` → answer in one deterministic sentence + render the existing Scale/Pause actions inline. Effort: S (~2 days). Risk: Low. Never hangs. Intelligence = current rules, but reliable.

### Approach B: Full reasoning brain (ideal, all at once)
A strong reasoning model with Meta action tools bound (pause/scale/create), guardrails, confirm→execute, built end-to-end. Effort: L (~1–2 wks). Risk: High — the current loop hangs, so this front-loads reliability + guardrail work before users get a working answer; "still not answering" persists longer.

### Approach C: Staged — reliable now, smart next (CHOSEN)
Ship A now on one spine, then layer B's reasoning over the *same grounded data* and the *same approve→act gate*. Reliability today, intelligence ceiling next, channel-agnostic contract for later. Effort: S then M.

## Recommended Approach — C, staged

**Phase 1 — Grounded router (~2 days). Fixes "not answering."**
- Add an intent check in the chat path (`src/app/api/brief/reply/route.ts` and the `/mello` agent entry): if the message matches ad-performance intent ("improve my ads", "how are my ads", "what should I do", "scale/pause"), *do not* enter the open tool-loop.
- Call `auditAccount(userId, primaryOrSelectedAccount, range='last_30d')`. Compose a deterministic 1–3 sentence answer from the structured result (spend, avg ROAS, top scale, top pause, spend today).
- Return the existing one-click actions inline (reuse the `mello_tasks` scale/pause rows the audit already writes). "Pause X — bleeding €Y/mo. [Do it]".
- Hard cap + graceful fallback already exist in `brief/reply`; keep them as the backstop.
- Result: typing the money question answers instantly, every time, with actions attached.

**Phase 2 — Reasoning layer (~1 wk). Makes it smart.**
- Feed the *audit result + per-ad table + competitor patterns + prior actions* into a strong reasoning model (Claude Opus/Sonnet via an adapter, or GPT) as structured context — never raw Graph, never un-grounded.
- The model proposes actions as `mello_tasks` (kind `meta_pause`/`meta_scale`/`meta_launch`) — it does not call Meta directly. Execution stays behind the existing confirm→`tasks/run` gate.
- Add guardrails: max budget step per confirm, no pause on a campaign spending < threshold without extra confirm, always store the pre-change value for one-click revert.

**Phase 3 — Channels (later, out of scope for this doc).**
- The Phase 1–2 contract is: `question → grounded answer + proposed action(s) → confirm → execute → revert`. That contract is transport-agnostic. Slack/WhatsApp/SMS become thin adapters over the same endpoint. Do not build until Phase 1–2 are proven in-app.

## Open Questions
- Which 3–5 actions are in scope for v1 execution? (Proposed: pause campaign, scale campaign budget +X%, resume/undo. Launch-new-ad is bigger — defer.)
- Intent detection: keyword/router in Phase 1, or a tiny cheap classifier? (Start with a keyword router; it's enough and can't hang.)
- Reasoning model choice for Phase 2 (Claude vs GPT) — decide when Phase 1 ships.
- Multi-account: does "improve my ads" mean the primary account, or all 7 aggregated? (Recommend: primary/selected, matching Reports and the brief card, to avoid mixed-currency nonsense.)

## Success Criteria
- **Reliability:** 100% of ad-performance questions return a grounded answer in < 5s (no hang), measured over a week of real usage.
- **Groundedness:** the answer's numbers match the Reports card for the same account/range (spot-check 10 sessions).
- **Action-through:** a user can go question → confirm → executed Meta change → visible in Meta, with a working revert, in one session.
- **Wedge proof (the real one):** ≥ N distinct users type the question and confirm at least one action within 2 weeks of Phase 1. If they read the answer but never confirm an action, the "employee" thesis is wrong and we stay an analyst.

## Distribution
Web service on the existing Vercel pipeline — no new distribution channel for Phase 1–2. Channels (Phase 3) are separate scope.

## Dependencies
- `auditAccount()` (done, `src/lib/meta/audit.ts`).
- `mello_tasks` + `tasks/run` approve→act (done, migration 126).
- `MetaClient.pauseCampaign` / `scaleCampaignBudget` (done, `src/lib/meta/client.ts`).
- The chat entry points: `src/app/api/brief/reply/route.ts` (brief composer) and the `/mello` agent (`src/lib/mello/agent.ts`) — Phase 1 adds the router before the loop.

## The Assignment
Before writing Phase 2's reasoning, do the job by hand once, on your own live account, and time it: open the audit, pick exactly one campaign to pause, pause it in Meta, and write down *every judgment call you made* and how long it took. That transcript — "I paused it because frequency was climbing and ROAS dipped two days straight, but I left the other low-ROAS one because it just launched" — is the literal spec for Mello's reasoning layer. You can't make Mello a good media buyer until you've written down what a good media buyer actually decides. One account, one pause, one page of notes.

That's a delegation instinct, and it's the whole difference between an analyst product and an employee product. You reached for the harder, more valuable one without being pushed.
- When I said "you're standing on the answer already — Reports does this," you didn't get defensive. You said "you are right… how can we make it more intelligent." You took the reframe and immediately asked the better question. That's rare; most people argue for the plan they walked in with.
- You deferred Shopify yourself — "we'll do Shopify later, Facebook ROAS is also quite accurate right now." You're sequencing by leverage, not by what sounds impressive. That's the same muscle that keeps you from building the omnichannel platform before the core answers one question.
